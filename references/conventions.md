# 日期、权限和保留约定

先查服务器与用户既有约定，继承明确决定。以下是可复用的命名示例；使用明确时区，可选UTC或团队约定的时区，不擅自迁移历史。

## 新产物格式

以下示例使用 `Asia/Shanghai`（UTC+08:00）；实际部署明确选择时区，目录格式保持一致：

```text
YYYY-MM-DD_HH-MM-SS__类型
2026-10-29_16-10-00__full/
2026-10-29_16-10-00__cert/
2026-10-29_16-10-00__html/
2026-10-29_16-10-00__nginx-logs/
```

同秒冲突追加__02、__03，不覆盖；不含冒号，便于跨系统文件操作。文件名中的时间取本次备份或生成批次的开始时间。manifest注明：

```json
{
  "created_at": "2026-10-29T16:10:00+08:00",
  "completed_at": "2026-10-29T16:10:05+08:00",
  "timezone": "Asia/Shanghai",
  "automatic_deletion": false
}
```

用显式时区生成时间，不为命名调整系统时区。示例shell：

```bash
TZ=Asia/Shanghai date '+%Y-%m-%d_%H-%M-%S'
```

类型由资料含义决定，日志仍可用__nginx-logs，不必全改成__backup。

## 日志

access.log/error.log/cron.log为固定活跃名，归档目录带完整时间。单次执行日志可用 `<完整时间>__<任务>-<对象>__<唯一ID>.log`。

按内容日期拆分的文件可用 `YYYY-MM-DD__access_0001.log.gz`，外层批次仍使用完整时间；明确这是内容日期而非创建时间。

保留历史原名、原日志行时区、内部事务UTC/uuid/指纹，不为视觉一致破坏引用。发现新程序不一致，记录差异并在授权修改时备份验证；写技能本身不授权重命名生产文件。

## 权限、保留和清单

- 受限备份外层0700，私钥/账户/环境资料及归档0600。
- 备份保留文件内容、UID/GID、权限、mtime、链接，按需求保存ACL/xattrs。
- 保留策略必须明确。永久保留、按期保留或异地备份都应经过任务范围确认，不因为示例中的automatic_deletion=false就自动套用。
- 经解压校验的无损压缩不等于历史淘汰；keep_raw等额外保留标志继续尊重。
- 清单记录来源、范围、时区、校验、状态和恢复依赖；失败标为failed，不因产生文件就宣称完成。
- 同机归档不等于异地容灾，文件快照不等于数据库一致性备份。
