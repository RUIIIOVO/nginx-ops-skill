# SSL 自动签发与证书事务

## 接入现有系统

先识别已有ACME客户端、CA、DNS/HTTP挑战方式、凭据来源、安装目标、定时任务及reload回调。不要为审查切换CA或重复创建续期任务；凭据不输出到聊天。

区分三层：签发账户及CA状态、候选材料、线上Nginx实际读取材料。自动资格来自现有显式登记/客户端状态，不能只因文件在cert目录就认定已纳管。

只读检查应包含域名/SAN、有效期、链、私钥匹配、线上实际证书指纹、所有名称及特殊端口、候选与线上差异。证书好不代表HTTP业务好。

## 推荐发布链

在需要新建或改造系统时：

1. 客户端只写候选；现有发布程序拥有线上写入和reload。
2. 先处理未提交事务，检查是否已有有效新候选，避免签发与发布脱节。
3. 校验SAN、链、有效期、私钥匹配，再完整备份旧证书对并校验。
4. 同步prepared事务，切换完整证书对，再记录switched。
5. Nginx检查、平滑reload，实际握手核对新指纹，成功committed。
6. 失败恢复完整旧证书对，reload并核对指纹和TLS有效性；恢复失败阻止后续发布。

原子目录交换、版本指针等依现有布局决定；优先复用成熟实现，不为外观重做。证书链和私钥逐文件覆盖可能产生中间不匹配，不能用它替代已有原子机制。跨文件系统或能力不支持时停止，不偷偷降级。

cert挂载根保留；若整根直接挂载不能rename替换，只有其内部子目录在消费者支持下可交换。

## 新增、续期与回滚

先查真实CLI，再给具体命令。plan/status和dry-run与reconcile/enroll/force语义分开；force通常真实签发、有CA限流，不用于普通诊断。

新增证书不自动等于新增业务路由；上线应同时验证站点引用和实际TLS。旧域名仍有HTTPS重定向就仍需有效证书，不能只因不是主域就删续期。

回滚要求当前版本对应事务，备份可信，旧证书覆盖名称且未过期。文件恢复到旧指纹但已过期要明确报告；新候选仍存在时后续协调可能重新发布，不能靠反复回滚表达长期策略。

## 灾难恢复

Nginx目录包通常不包含外部ACME账户和历史证书。恢复签发需要账户/CA状态及挑战凭据；恢复历史回滚需要事务关联备份。含私钥/账户的资料受限保存，Nginx不直接从公开备份路径读证书。

程序运行日志和签发日期按统一命名约定；原内部事务ID保留。文档不能宣称执行过真实CA签发、购买或回调测试，除非确有证据。
