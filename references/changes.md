# 备份、配置发布和回退

## 改动前

记录涉及文件内容哈希、元数据、链接、挂载、服务/容器身份，明确要改变的响应和不应改变的行为。读取现有备份脚本，不能仅凭名字full假定涵盖全服务器。

按实际范围补充：Nginx配置/脚本/当前证书、外部静态根、签发账户、历史证书与事务、相关cron/timer、容器定义。数据库需要单独一致性方案。持续写入日志必须说明备份时点/前缀语义。

备份写到公开根之外，含私钥/环境的外层0700和归档0600；保留UID/GID、权限、mtime、链接，必要时ACL/xattrs。检查压缩完整性和内容校验，重要变更在隔离目录验证恢复。备份失败停止修改。

## 候选及发布

- 用现用版本Nginx验证，不因验证拉最新版镜像。配置/证书只读挂载；临时请求端口仅回环绑定。
- 备份完成后重新核对待改对象未漂移，保护其他会话的修改。
- 协调现有共享锁，覆盖写入、检查和reload；注意调用已有程序的嵌套锁。
- 原生或容器语法检查通过后平滑reload，不默认restart。
- 单文件bind mount保留inode；直接挂载目录原位更新。根目录内子文件可原子替换。不要将本地rename的直觉套到容器挂载根。
- 路径迁移须检查文件系统、持有文件描述符和程序依赖，保留迁移映射和原清单，不能重写已签名/校验的历史manifest。

## 前后对比

同一批定义用于候选、生产T0/T1/T2；保存状态、Location、Content-Type、正文哈希、TLS身份。

至少按业务覆盖：官网/后台、实际JS/CSS/MIME、SPA深链及缺失资源、API鉴权、媒体、法律页、重定向、正常和未知Host/SNI。存在WebSocket/SSE时增加相应非破坏性检查。

GET405只能证明POST路由可达，不能宣称支付/回调验签成功；没有明确测试授权不发支付POST。原有401/404/502按基线，不要求所有响应200。

nginx-T只表示磁盘配置；确认真实请求和必要进程状态。外部验证连接源站IP时保持域名/SNI，不能用-k掩盖证书问题。

出现超出预期的资源缺失、MIME、TLS、安全边界或业务差异时按本次范围回退，避免全量快照覆盖后续独立证书/配置更新。

## 前端和部署源

线上只保留当前版本还是保留current/releases，沿用用户决定，不为简单更新无谓引入版本架构。历史保留在外部备份区。

直接挂载的静态根可逐文件准备/原子替换、入口最后、失败回滚；不能称为整树原子或保证绝对零中断。下载/上传目录与构建产物分离，发布不能先rm整个在线根。

支持只发布前端，避免无意重建后端。后端替换须另存原镜像/容器/环境及恢复方式，保留持久化挂载，失败事务不能盲目重试。生产Compose与本地源保持一致，检查插件或独立命令能力。

完成后同步文档和本地模板，运行适当语法/行为测试，清理临时验证实例。恢复资料和未完成事务不当临时垃圾清理。
